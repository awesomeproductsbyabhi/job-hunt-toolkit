# Interview kickoff

Run this when an interview is confirmed. Applications are manual only; never contact anyone on the user's behalf.

## Load first
1. The interview playbook (`playbook/INTERVIEW_PLAYBOOK.md`): process, answer rules, rubric, learnings log.
2. The user's story bank: standard answers, a numbers sheet with a status for each figure (verified, team-reported, plan, open), one card per story.
3. The company's prep doc, if one exists.
4. The user's career notes (the source of truth). If they disagree with the story bank, the career notes win and the card is fixed.
5. The pipeline row for this role.

## Steps
1. Record the confirmed details (round, date, time, format, duration, interviewer) in the pipeline row and the prep doc. Mark anything the company did not confirm as typical, not confirmed.
2. Gather intel: the job description themes, company and product news, competitors, and questions candidates report for this company and role. Tag every reported item "reported, unverified" with source and date. Never invent what candidates say. If a page cannot be opened, give the user the exact search to run and ask for a pasted copy.
3. Add a page for this round: likely questions, the three stories to lead with, the follow-ups each invites, the numbers to say.
4. List every figure in those stories that is an estimate, plan or open, so the user says "about" or leaves it out.
5. Check the standard answers (reason for leaving, notice period, years of experience, location, pay approach) match what the user told other companies. Never fill in pay figures; ask.
6. End with what is still open and a timeline. If the interview is under 48 hours away, use the short-notice order.

## Rules
Only claims that trace to the user's career notes or resume. Credit accurately: if someone else built a piece, write "led product on", not "built". No partner or customer names. Always link the prep doc in the pipeline row.
